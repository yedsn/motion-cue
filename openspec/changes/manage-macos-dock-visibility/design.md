# Design

## Context

当前 Tauri 宿主在管理窗口收到关闭请求时统一阻止销毁并调用窗口隐藏；所有菜单栏、托盘菜单和外部 `open` 命令最终通过 `app_open` 显示、还原并聚焦同一个窗口。后台冷启动路径也会隐藏管理窗口。

macOS 构建已由发布工作流生成 Apple Silicon 和 Intel 的应用包，Tauri 版本提供仅限 macOS 的 Dock 可见性接口。当前代码未调用该接口，因此隐藏管理窗口不会同步隐藏 Dock 图标。规格见 `specs/macos-app-lifecycle/spec.md`。

## Goals / Non-Goals

**Goals:**

- 将 macOS Dock 图标状态收敛到“管理窗口可见时显示、管理窗口隐藏时隐藏”的单一规则。
- 复用现有统一打开入口，保证菜单栏、检查更新、CLI `open` 和第二实例唤醒行为一致。
- 区分正常 GUI 启动与后台调用冷启动，避免后台播放短暂出现 Dock 图标。
- 让平台条件清晰且可测试，确保 Windows 行为不回归。

**Non-Goals:**

- 不改变菜单栏菜单结构、窗口视觉样式或动画覆盖窗口行为。
- 不让普通播放、自定义链接播放或动画覆盖窗口自动显示 Dock 图标。
- 不新增“始终显示 Dock 图标”等用户设置。
- 不调整 macOS 签名、公证、安装或自动更新流程。

## Decisions

### 1. 以管理窗口可见性作为 Dock 状态来源

Dock 图标是否可见由管理窗口的打开、关闭和后台启动转换决定，不单独持久化配置。正常 GUI 启动沿用 macOS 默认的可见 Dock 状态；关闭窗口和后台启动切换为隐藏；重新打开窗口切换为显示。

这样可以避免配置状态与真实窗口状态不一致。未选择在前端维护状态，因为窗口关闭、单实例转发和后台冷启动都由 Rust 宿主管理，前端可能尚未加载或已经不可见。

### 2. 使用 Tauri 的 macOS Dock 可见性接口

宿主通过 Tauri 提供的 `set_dock_visibility` 切换 Dock 图标，并使用编译期 macOS 条件封装平台差异。非 macOS 平台的辅助操作为空操作，因此现有窗口生命周期无需复制成多套分支。

未选择修改应用包的 `LSUIElement` 配置，因为静态菜单栏应用模式无法满足“窗口打开时恢复 Dock 图标”的动态需求；也不直接调用 AppKit，以避免新增原生绑定和绕过 Tauri 的运行时处理。

### 3. 打开路径先恢复 Dock，再显示并聚焦窗口

统一打开入口在 macOS 上先请求显示 Dock 图标，然后执行现有的窗口显示、取消最小化和聚焦操作。菜单栏“打开”、菜单栏“检查更新”、CLI `open`、单实例 GUI 唤醒及其他语义为打开管理界面的调用继续复用该入口。

Dock 状态切换在 macOS 内部可能异步完成，因此实现应把聚焦失败作为可诊断错误处理，并在真实 macOS 环境验证首次打开与连续关闭/打开。若直接聚焦在目标系统上不稳定，可在不改变规格的前提下通过主线程调度一次后续激活或聚焦。

### 4. 关闭路径先隐藏窗口，再隐藏 Dock

管理窗口关闭事件继续阻止窗口销毁，随后隐藏窗口，并在 macOS 上隐藏 Dock 图标。只有 `main` 管理窗口参与此转换；动画覆盖窗口的显示和隐藏不得改变 Dock 状态。

先隐藏窗口可避免 Dock 状态切换期间留下无入口的可见窗口。关闭处理中的失败应记录诊断信息；即使 Dock 隐藏失败，也不能让关闭请求意外终止整个应用。

### 5. 后台冷启动在初始化完成后同步隐藏 Dock

现有 `LaunchIntent::Background` 路径在建立菜单栏、IPC 和应用状态后隐藏管理窗口。该路径同时隐藏 Dock 图标，确保由 CLI 播放或协议调用拉起的常驻实例不会表现为前台应用。正常 `LaunchIntent::Gui` 不执行隐藏转换。

不改变播放型自定义链接的语义：它们触发动画而不打开管理窗口；只有明确的管理界面打开操作才恢复 Dock。

### 6. 将平台决策抽成可单元测试的生命周期动作

把“GUI 启动、后台启动、打开管理窗口、关闭管理窗口”映射为窗口和 Dock 动作的纯决策保持在小型辅助逻辑中，并通过 Rust 测试覆盖状态转换。真实 Dock 是否出现仍需在 macOS 桌面验收中确认，因为 Windows CI 和无界面单元测试无法观察系统 Dock。

### 7. 延迟仲裁 macOS Reopen 与播放型 URL Scheme

macOS 通过 `motioncue://play/...` 唤醒后台实例时，可能在同一轮激活中同时产生 URL 打开和应用重开事件。应用不能把伴随的 `Reopen` 直接解释为用户点击 Dock，否则会错误恢复 Dock、显示管理窗口并抢占焦点。

收到 `Reopen` 后短暂延迟恢复动作；若延迟窗口内收到有效的播放型 URL，则取消对应的恢复动作。独立发生的 Dock 点击或应用重开仍复用统一管理窗口打开入口。仲裁只影响 macOS 应用激活，不改变 URL 解析和动画播放语义。

播放事件重试、会话超时和显示器拓扑轮询包含同步休眠，这些工作通过 Tauri 的阻塞任务池执行，避免占用普通异步工作线程并拖慢后台 WebView 的事件处理。

动画覆盖窗口禁用 WebView 后台节流，避免窗口长期隐藏后被 WebKit 挂起，重新显示时出现计时器、`requestAnimationFrame` 或 Worker 恢复延迟。该设置只应用于按需显示的覆盖窗口，管理窗口仍使用默认节流策略。

### 8. 后台状态使用 Accessory 激活策略

实机验证表明，仅在 `Opened`/`Reopen` 回调后取消窗口恢复仍然太晚：LaunchServices 在投递 URL 之前已经可能激活 Regular 应用，导致 Dock 出现和调用程序失焦。管理窗口隐藏和应用冷启动阶段必须持续使用 `NSApplicationActivationPolicyAccessory`；显式打开管理窗口时再切换为 `Regular`，恢复 Dock 并聚焦窗口。

应用在进入事件循环前先采用 Accessory 策略并隐藏 Dock，同时将管理窗口配置为默认不可见，并关闭 Tauri 冷启动时“忽略其他应用并激活自身”的行为。正常 GUI 启动短暂等待 URL 打开事件；若没有后台 URL 才切换为 Regular 并显示管理窗口。这样避免系统在 URL 回调到达前创建关键窗口或抢占前台，同时覆盖已运行的后台实例和由 URL Scheme 拉起的冷启动实例。

后台播放回调不得重复执行 Accessory 或 Dock 隐藏转换；这些转换只在进入后台生命周期时执行一次。Tauri 在 macOS 上的普通窗口 `show()` 会调用 `makeKeyAndOrderFront`，因此动画覆盖窗口改用 AppKit `orderFrontRegardless` 在主线程置前，只显示覆盖层而不让其成为 key window。这样即使管理窗口从未显示，overlay WebView 也能独立初始化和播放。

深链监听由 macOS 应用事件循环触发，不能在该回调中同步执行可能创建 WebView 窗口的 `play_request`。Tauri 的窗口创建会向事件循环发送消息并等待结果，若调用者正是事件循环线程就会互相等待。协议回调只负责解析请求和设置 Reopen 抑制，实际播放投递到阻塞任务池执行，确保首次后台播放可以创建 overlay 而不锁死应用。

## Risks / Trade-offs

- [macOS Dock 显示转换是异步的，快速连续开关可能造成聚焦延迟或系统图标残留] → 复用 Tauri 运行时的节流处理，避免自行反复调用底层 AppKit，并在验收中覆盖快速关闭后立即重开。
- [Dock 切换成功但窗口显示或聚焦失败会形成状态短暂不一致] → 统一入口按固定顺序执行并返回错误，记录诊断；重新点击菜单栏仍可重试。
- [只有 Windows 开发机时无法完整自动验证 Dock] → 保留平台无关决策单元测试，并在 macOS Apple Silicon 或 Intel 真实桌面环境执行验收清单。
- [隐藏 Dock 后用户只能从菜单栏重新进入] → 菜单栏图标必须在关闭操作后继续存在；退出仍通过菜单栏显式完成。
- [URL 打开与 Reopen 的系统回调顺序不固定] → 同时覆盖“Reopen 先到”和“URL 先到”两种顺序，并用短时间抑制窗口消除竞态。
- [系统可能在 URL 回调前激活 Regular 应用] → 后台生命周期持久使用 Accessory 策略，关闭冷启动主动激活并让管理窗口默认隐藏，不依赖回调发生后再抢救性隐藏 Dock。
- [在每次播放回调中重复隐藏 Dock 可能重入 macOS 进程类型转换] → Dock 与激活策略只在生命周期转换时修改，普通播放保持当前后台状态。
- [普通 `show()` 可能让非聚焦 overlay 仍尝试成为 key window] → macOS 使用 `orderFrontRegardless` 非激活式显示 overlay，其他平台保留 Tauri `show()`。
- [深链回调在主事件循环内同步创建 overlay 会自锁] → 将协议播放投递到阻塞任务池，避免窗口创建同步等待当前事件循环。

## Migration Plan

1. 增加 macOS Dock 可见性辅助逻辑，并让非 macOS 构建保持为空操作。
2. 将统一管理窗口打开入口接入 Dock 恢复，将主窗口关闭与后台启动路径接入 Dock 隐藏。
3. 增加生命周期动作测试，并运行现有 Rust、前端与构建检查。
4. 在真实 macOS 上验证正常启动、关闭、菜单栏重开、检查更新、CLI `open`、后台冷启动播放、快速关闭重开和退出。

该变更不迁移用户数据。若发布后出现 macOS 窗口恢复问题，可回退应用版本；Windows 行为不依赖此平台分支。
