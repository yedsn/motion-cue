## Context

该仓库目前只有 OpenSpec 规划骨架，没有应用代码。MotionCue 需要同时处理 Windows 协议注册、命令行调用、单实例转发、托盘生命周期、多显示器透明窗口、音频播放、可编辑动画目录和不可信 Web 插件，因此属于跨 Rust 宿主与 Web 渲染层的桌面架构。需求边界见四份 delta spec；本设计只说明实现方式。

可复用参考来自工作日报助手中已验证的 Tauri 2 透明置顶窗口、托盘运行方式，以及基于 `canvas-confetti` 与 Howler.js 的完成动画和本地 WAV 播放。MotionCue 不直接依赖原项目代码或运行时数据，迁移时只提取通用动画参数、素材及必要的渲染逻辑。

## Goals / Non-Goals

**Goals:**

- 建立 Windows 优先、可打包分发的 Tauri 2 桌面应用，同时保持协议层和播放模型可移植。
- 让自定义链接和命令行最终进入同一套类型化播放请求管线。
- 保证覆盖层不抢焦点、不拦截输入，并能在多显示器和异常路径下可靠清理。
- 将内置动画、配置型动画和 Web 插件统一成可解析、可验证、可停止的播放会话。
- 在不向插件暴露 Tauri 或系统桥接的前提下提供足够的 Web 动画能力。
- 让配置和插件安装可以恢复、回退、导入和升级，而无需引入数据库。

**Non-Goals:**

- 第一阶段不支持 macOS、Linux 的正式发布和平台专项协议注册，只避免在领域模型中写死 Windows。
- 不提供远程插件市场、在线资源加载、账号、云同步、动画调用统计或遥测。
- 不支持 DLL、Rust、Node、PowerShell 等原生插件，也不允许插件申请通用系统权限。
- 不提供可视化关键帧编辑器、复杂视频编辑器或任意 JavaScript 的“配置型动画”。
- 不保证动画覆盖安全桌面、UAC 提权界面、锁屏或全屏独占游戏。

## Decisions

### 1. 使用 Tauri 2 + Rust 宿主和 Vue 3 + TypeScript 管理界面

Rust 宿主负责协议、命令行、单实例、IPC、窗口、配置文件、插件包和安全边界；Vue 应用负责动画目录、编辑表单、预览与内置渲染器。覆盖窗口加载专用的轻量播放页面，不加载完整管理界面。

选择 Tauri 是因为项目需要原生窗口和协议能力，但动画本身适合 Web 渲染；它也能复用现有项目经验。未选择 Electron，原因是常驻工具的内存和安装体积更高，且 Node 能力会增加插件隔离难度；未选择纯 Win32/WPF，是因为 Web 插件和 Canvas/SVG 动画的开发体验较差。

### 2. 所有入口转换为统一 `InvocationRequest`

自定义链接、命令行、管理界面预览和托盘操作首先解析为同一结构：来源、命令、参数、请求时间和可选响应通道。Rust 层完成命令规范化、目录解析、参数 schema 校验和去重指纹计算，只有验证后的 `PlaybackRequest` 才发送到播放协调器。

自定义链接采用 `motioncue://play/<command>` 为主格式，并兼容 query 形式。CLI 提供 `play`、`list --json`、`stop` 和 `open`。调用入口不直接操作 Webview，避免各入口出现不同校验或错误行为。

### 3. 通过单实例插件和本地进程间转发复用运行实例

应用使用 Tauri 单实例能力接收第二进程参数，并将请求送入主实例内的协调器。CLI 与桌面应用由同一可执行程序提供：无运行实例时建立托盘与播放运行时，有实例时转发后退出。CLI 需要结果时，使用带随机请求标识和严格超时的本地 IPC 响应通道；IPC 只接受当前用户，消息使用长度前缀 JSON 且设置最大尺寸。

未采用常驻 HTTP 服务，因为端口、防火墙、来源认证和跨站触发会扩大攻击面；未只依赖自定义链接，因为 Hook 需要退出码和 JSON 输出。

### 4. 每个目标显示器使用一个专用透明覆盖窗口

播放协调器维护 `monitor-id -> overlay window` 池。窗口默认隐藏，播放前按当前物理显示器边界创建或调整，设置为透明、无边框、置顶、跳过任务栏、不可聚焦并启用系统级鼠标穿透。播放完成后隐藏而非销毁，以降低高频调用延迟；显示器拓扑变化时重建受影响窗口。

每个覆盖窗口收到相同的会话描述和自己的画布尺寸。音效只由主播放协调器播放一次。管理窗口与覆盖窗口使用不同 label、路由和最小权限集合。

未采用一个跨越虚拟桌面的巨大窗口，因为负坐标、混合 DPI、显示器旋转和窗口管理更脆弱；独立窗口更容易验证和清理。

### 5. 播放协调器采用单活动会话和最新请求覆盖策略

第一阶段同时只运行一个逻辑播放会话。收到新有效请求时先向全部覆盖窗口和音频层发送停止，等待短暂清理确认后启动最新请求。300 毫秒内命令和规范化参数完全相同的请求合并；参数不同则按最新请求替换。每个会话有正常时长和不超过 60 秒的宿主安全超时。

该模型避免不同动画和音效混合，也让紧急停止可靠。未采用无限队列，因为 Hook 突发会导致过期庆祝连续播放；未来如需组合场景，应引入显式场景时间线，而不是隐式排队。

### 6. 使用版本化 JSON 目录和受管理资源目录，不引入数据库

设备配置、动画目录和插件登记使用带 `schemaVersion` 的 JSON 文件。保存流程为：写临时文件、刷新、校验、原子替换，并保留一个上次有效备份。音频、动画包和插件资源复制到应用数据目录，配置仅保存受管理的相对资源 ID，不保留任意外部绝对路径。

目录模型使用带 `kind` 判别字段的联合类型：`builtin`、`configured`、`web-plugin`。命令和别名在构建索引时统一小写并检测冲突。内置动画不可删除，但可以禁用、调整音效或恢复默认值。

SQLite 对第一阶段的小规模文档配置属于额外复杂度；若未来需要调用历史、搜索市场或大量版本记录，可在保持领域模型不变的前提下迁移。

### 7. 配置型动画只组合受信任渲染器和 schema

配置型动画只能引用应用内注册的渲染器，如 confetti、badge、pulse、ring、shake 和组合式 completion。每个渲染器声明 JSON schema、默认值、可外部覆盖参数及安全范围；用户不能插入 JavaScript、HTML 或远程 URL。

内置 `task-complete` 将迁移现有的左右底部多段彩带、自定义粒子形状、顶部提示卡片和本地成功音效，但移除与事项业务状态相关的判断，仅消费通用文本和强度参数。

### 8. 音频由宿主控制的统一音频服务播放

动画定义引用音效资源 ID、音量、延迟和启用状态。播放协调器在会话开始时调度一次音效，替换或停止会话时立即取消延迟任务并停止当前声音。插件只能通过 SDK 请求清单中声明的音效 ID，不能自行创建任意外部音频源。

实际播放可由覆盖页面中的单一 Howler.js 音频宿主承担，也可由 Rust 音频层承担；首版优先 Howler.js，以复用已验证的格式和行为。无论实现放在哪里，音频控制接口归播放协调器所有，并且不随显示器复制。

### 9. Web 插件在无 Tauri 权限的隔离 Webview/iframe 中运行

插件包包含 `manifest.json`、单个入口 HTML/JS、只读本地资源及可选声明音效。安装时先解压到临时目录，拒绝绝对路径、路径穿越、符号链接、过大资源、未知格式和重复 ID，完整验证后再原子移动到版本目录。

插件运行页面不注入 Tauri API、Node API 或应用命令。使用唯一会话 iframe，配置严格 sandbox，仅保留脚本执行所需能力，不允许表单、弹窗、顶层导航、下载、同源提升或设备权限。资源通过宿主生成的会话级虚拟来源或显式映射提供，CSP 使用 `default-src 'none'`，只开放包内脚本、样式、图片、字体、媒体、blob Worker 等已声明渲染来源，并将 `connect-src` 固定为 `none`。

插件 SDK 建立在校验过的 `postMessage` 消息之上，消息带协议版本、会话 ID、类型和有限载荷。宿主只接受 `ready`、`complete`、`error`、`sound`，并限制消息大小和频率；插件接收 `play`、`stop` 和尺寸信息。每次播放创建新的插件上下文，结束后销毁，避免跨会话持久状态。

不使用普通同源页面直接加载插件，因为 CSP 不能替代宿主 API 隔离；也不使用动态远程代码，因为离线可审计是安全承诺的一部分。

### 10. 管理界面负责显式信任和可诊断性

插件安装完成后默认禁用，界面展示来源文件、插件 ID、版本、声明的 WebGL/Worker 能力、包大小和命令。用户确认后才启用。界面提供预览、最近一次错误和重置配置；诊断日志只保存时间、来源、命令、结果和非敏感错误，不默认保存完整外部文本参数。

托盘菜单至少提供打开 MotionCue、停止全部动画、全局静音和退出。关闭管理窗口只隐藏到托盘；退出会停止全部会话并释放协议、IPC 和托盘资源。

### 11. 自动验证与桌面验收分层

Rust 单元测试覆盖 URL/CLI 解析、命令索引、参数校验、去重、配置原子写入和插件包路径安全。TypeScript 测试覆盖渲染器 schema、SDK 消息校验和播放生命周期。集成测试使用测试配置目录验证第二实例转发、配置恢复和插件安装回滚。

Windows 桌面验收覆盖双显示器混合 DPI、焦点保持、鼠标穿透、协议冷启动、CLI 退出码、音效只播放一次、显示器热插拔和失控插件紧急停止。安全验收使用恶意测试插件验证网络、文件、宿主 API、弹窗和导航均不可用。

## Risks / Trade-offs

- [Windows WebView 的透明窗口和鼠标穿透行为在显卡或远程桌面环境中可能不一致] → 启动时能力探测，失败时不显示会拦截输入的窗口，并记录明确诊断；维护覆盖层专项验收清单。
- [全屏独占应用或安全桌面可能覆盖 MotionCue] → 文档明确支持边界，不尝试使用注入、系统钩子或提升权限绕过操作系统限制。
- [Web 插件允许 JavaScript，仍可能造成 CPU/GPU 占用] → 每次播放使用可销毁上下文、限制总时长与消息频率，提供紧急停止；首版记录资源异常但不承诺精确跨平台 CPU 配额。
- [WebView 的来源隔离、CSP 或自定义协议配置错误可能扩大插件权限] → 插件运行页面和管理页面分离权限集合；建立恶意插件自动测试并默认拒绝未知能力。
- [单可执行程序同时承担托盘和 CLI，错误的启动模式可能导致 Hook 等待] → 入口先解析纯查询/转发意图，CLI 使用严格超时和确定退出码，集成测试覆盖无实例与已有实例两条路径。
- [最新请求覆盖策略可能丢弃用户期望连续播放的效果] → 首版将行为写入规格并提供明确日志；未来使用显式场景/序列能力扩展，而不是改变默认并发语义。
- [JSON 文件未来可能不适合大量动画和调用历史] → 配置访问集中在仓储接口，资源使用稳定 ID，便于后续迁移到 SQLite。

## Migration Plan

1. 初始化 Tauri/Vue 工程和版本化配置目录，先实现管理窗口、托盘与默认目录。
2. 建立统一调用解析、单实例转发和覆盖窗口池，以简单测试动画验证窗口安全属性。
3. 实现配置型渲染器和音频服务，再迁移工作日报助手的任务完成动画及 WAV 资源，保留原应用实现不变。
4. 完成动画管理、导入导出和配置恢复后，再启用 Web 插件安装与沙箱运行。
5. 通过自动测试和 Windows 多显示器、安全插件验收后生成安装包并注册 `motioncue://`。

项目为新应用，没有用户数据迁移。若发布后升级失败，安装程序可回退应用版本；配置加载器必须保留上一个有效文件，并拒绝用较新版本无法理解的配置覆盖备份。
